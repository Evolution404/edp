## 4. Five USB media classes — critical current rule

This logic was implemented immediately before this handoff. Do not regress it.

Drive reads a small metadata sample only:

```text
LBA0
LBA4
LBA7
LBA11
LBA12
```

and classifies whole USB media as:

```text
standardEncrypted   factory-standard encrypted EDP
legacyNoPassword    old no-password conversion
currentNoPassword   latest no-password conversion
unrecognizedEDP     EDP evidence exists but structure is not safely recognized
ordinaryUSB         no reliable EDP evidence
```

**Only `standardEncrypted` may enter raw lease / password / mount handling.**

All other classes remain owned by macOS / Disk Arbitration / Finder. Drive must not create an EDP mount session for them.

### 4.1 Factory-standard encrypted EDP

The current fail-closed gate requires the standard geometry to agree across all relevant structures:

```text
LBA7 entries:  [1, 2, 4]
LBA12 entries: [1, 2, 4]

entry0 is Boot/type 1

LBA7 entry0 start/size
      == LBA12 entry0 start/size
      == physical MBR first partition start/size
```

LBA11 must also recover a valid device identity for the actual VID/PID/capacity.

Real Lexar/SanDisk captured standard fixtures validate this gate.

Known real standard geometry example:

```text
MBR partition 1:
type    0x0e
start   63
sectors 20417
bytes   10,453,504

LBA12 entry0:
type    1
start   63
size    10,453,504 bytes
```

## 7. Drive service lifecycle and menu UI

### 7.1 Service lifecycle

The service plist intentionally has neither:

```text
KeepAlive
RunAtLoad
```

because the user must be able to stop it explicitly.

UI lifecycle:

```text
Start
  -> desired-running=true
  -> ensure registration
  -> XPC connection demand-launches service
  -> live health reply required

Stop
  -> XPC requestGracefulShutdown
  -> unmount sessions
  -> release DiskImages2
  -> stop macFUSE transports
  -> close retained raw fds
  -> stop monitor
  -> process exits normally
  -> no automatic resurrection

Restart
  -> graceful Stop
  -> wait for disconnect/exit
  -> Start
```

The XPC client accepts either interruption/invalidation timing and guards against stale old-connection callbacks overriding new state.

No product Stop/Restart path should use `kill -9` or `launchctl kickstart -k` as the normal lifecycle implementation.

Two separate real-device lifecycle wedges were reproduced and then closed during this work. The first involved failed transport/DiskImages2 teardown. The second, more fundamental issue was a direct `Darwin.unmount(2)` call inside the privileged Service: macOS/FSKit could leave that syscall in process state `U`, freezing the controller/XPC queue even though Swift-level timeouts existed.

Current hardening at `80f1cb6`:

- `hdiutil info/detach` helpers are bounded to 8 seconds;
- writable DiskImages2 attach is bounded to 15 seconds;
- every VFS unmount is isolated in a bounded `/sbin/umount` child process; the Service no longer calls `Darwin.unmount(` directly;
- normal user-volume unmount uses a bounded timeout, and forced hidden-transport unmount uses a shorter bounded timeout;
- child timeout handling is `TERM -> bounded grace -> KILL -> bounded verification`, so a stuck VFS child cannot drag the privileged Service into `U` state;
- teardown is strict top-down fail-closed: user filesystem -> published DiskImages2 BSD device -> hidden macFUSE mount -> transport process;
- if any upper layer remains mounted, lower layers are preserved and the operation returns an error rather than pretending success;
- explicit partition unmount, credential deletion, and whole-device eject propagate incomplete teardown errors; whole-disk eject never releases the raw lease or attempts physical eject while an encrypted session remains;
- App/CLI NSXPC callbacks are explicitly `@Sendable`, fixing the Swift 6 MainActor/XPC `SIGTRAP` seen in the older UI;
- installer preinstall/postinstall are also fail-closed: active hidden mounts block upgrade, stale `E`/zombie service processes are detected via `ucomm`, and bootstrap is bounded/retried.

Validation:

- `ValidateTransportLifecycle.swift` covers normal, TERM fallback, KILL fallback, and mounted fail-closed behavior;
- `ValidateBoundedVFS.swift` deliberately runs a stuck child and confirms the parent returns in bounded time (`~0.229 s` in the local probe);
- real Lexar lifecycle on `cd5bd49` completed two consecutive Stop -> Start cycles; both Stops completed in about 1 second with Service exit 0 and zero user/hidden/transport residue;
- `80f1cb6` adds the final explicit-unmount/eject error-propagation guard and has exact-head Drive CI success.

### 9.1 Right inspector layout fix

A bug was fixed immediately before this handoff:

- old implementation used SwiftUI `.inspector`;
- on the user's window width, macOS switched the inspector into overlay behavior;
- `DiskMapView` and `SectorView` contain horizontal scroll views;
- the inspector overlaid the right side without reducing the scroll viewport;
- rightmost content could therefore always scroll under the inspector and never be fully visible.

Current implementation uses a real `HSplitView` inside the detail column:

```text
Navigation sidebar | scrollable detail | inspector
```

When the inspector is visible it occupies real layout width. The right edge of sector/disk-map content should now stop to the left of the inspector instead of being hidden behind it.

Do not reintroduce `.inspector(` in `RootView.swift` without proving that this overlay bug cannot recur.

Relevant files:

```text
Apps/Studio/native/EDPStudioNative/Sources/RootView.swift
Apps/Studio/native/EDPStudioNative/Sources/DiskMapView.swift
Apps/Studio/native/EDPStudioNative/Sources/SectorView.swift
```

A follow-up visual regression was found after the first `HSplitView` conversion: the disk map still stopped at the end of Share and the Secret region was unreachable. Root cause was inside `DiskMapView`, not `HSplitView`: `GeometryReader` declared a fixed `960 * zoom` scroll extent, then each tiny region was independently clamped to a minimum width, so the rendered `HStack` became wider than the extent known by `ScrollView`. The Secret block was therefore painted outside the reachable scroll range. The map now uses a constrained proportional allocator: structural regions receive their readable minima first, Share receives the remaining proportional width, and the declared map width equals the real rendered extent.

The `HSplitView` conversion also exposed an inspector appearance regression. `.inspector` previously supplied a system material container around `InspectorView`; standalone `HSplitView` did not. The existing `.background(.background)` therefore resolved to an opaque panel. Keep the real split geometry, but render the inspector as a floating sidebar surface: 8 pt outer inset, continuous 22 pt corners, `ultraThinMaterial`, and macOS 26 `.glassEffect(.regular, ...)`. This intentionally mirrors the detached rounded-glass character of the left `NavigationSplitView` sidebar without returning to an overlay inspector.

Studio CI requires `HSplitView`, rejects `.inspector(`, and ratchets both the real disk-map extent and the floating translucent inspector surface.

## 14. Real-device safety rules

Known standard Lexar EDP identity from prior real-device work:

```text
stable ID:
disk&ven_lexar&prod_usb_flash_drive#49979b696404e74de01c

VID:PID:
21c4:0cd1

capacity:
124,736,503,808 bytes
```

Never assume the BSD name (`diskN`) is stable.

For a real EDP USB:

### Allowed

- passive/raw read-only metadata inspection;
- normal filesystem-level test files on already mounted volumes;
- create -> sync -> hash -> unmount/remount -> verify -> delete test marker;
- product safe eject;
- performance reads/writes through the normal mounted filesystem path when explicitly part of acceptance.

### Forbidden unless the user explicitly requests a destructive conversion/restore task

- raw-sector writes during Drive acceptance;
- disk erase/format/partition commands;
- changing MBR/LBA metadata;
- overwriting real encrypted areas;
- silently converting standard <-> no-password media.

If there is uncertainty about whether a disk is the real EDP USB, stop before any write.
